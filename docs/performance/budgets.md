## 관문

### 미디의 윤리 도장 품질 보강 (2026-09-09)

- 기존 큰 미디·두 선택·120초 규칙을 유지하고 주제별 삽화 5종과 책상 매트가 있는 배경을 적용했다. 현재 장면 전용 11장 합계 637,720바이트(0.61MiB), 이전 452,090바이트 대비 185,630바이트 증가다.
- 삽화는 표시 150×130 안에 비율을 유지하며 실행용 289~320px, 알파 투명도와 품질 96을 보존한다. 실제 한 번에 보이는 삽화는 한 장이며 문제의 정답에 따라 이미지나 색을 바꾸지 않는다.
- 보존한 이전 버전을 포함한 공개 이미지 182개는 18.10MB로 에셋 관문을 통과했다. 신규 원화·투명 배경 실험은 배포 폴더 밖에 보존했다.
- 자동 이동은 프레임 상한과 남은 거리 상한을 함께 적용한다. 양쪽 도장 근처의 느린·불규칙한 프레임에서 목표를 지나치며 입력이 잠기는 문제를 재현하고 회귀 검사로 검증했다.
- 도장 타격·미디 준비와 반응·효과음의 타격 기준은 375ms로 맞췄다. 3·5연속 성공만 짧게 표시하며 트윈·비행 이미지·음원은 카드 교체와 씬 종료에 맞춰 정리한다.

### 미디의 윤리 도장 개편 측정 (2026-09-05)

- 현재 기능은 새 배경·두 도장·고해상도 미디 3방향을 WebP 여섯 장, 합계 452,090바이트(0.43MiB)로 불러온다. 고객·창구·서류 이미지·마스크 필터는 사용하지 않는다.
- 미디 표시 크기는 214×275이며 원본에서 약 460×590 실행용 이미지를 파생한다. 한글과 판정 자국은 코드로 고해상도 렌더링한다. 새 배경은 1672×941, 도장은 440×543 / 440×526이다.
- 보존한 이전 버전을 포함한 공개 이미지 176개는 17.84MB로 예산 안에 있다. 신규 원화와 실험은 배포 폴더 밖에 보존한다.
- 한 선택만 이동·판정으로 연결하며 연타를 예약하지 않는다. 이동은 프레임 상한을, 120초 시계는 실제 경과 시간을 적용한다. 정답 1.2초·오답 2.6초 동안 중복 채점을 막는다.
- 그림 여섯 장의 메타데이터, 40개 균형 사례, 단일 선택·연습 재시도·마감·연속 진행과 기존 미니게임 모델을 검사하고 전체 `npm run verify`를 통과했다.

- 간소화 후 현재 장면은 원화 6종을 WebP 합계 337,930바이트(약 0.32MiB)로 불러온다. 이전 창구판 578,190바이트에서 약 42% 줄었다. 방 1672×941, 서류 885×532, 도장 308×380 / 308×368, 단일 손님 608×426 / 608×425이다.
- WebP 품질 96, 투명 소품 알파 품질 100을 사용한다. 원본을 인위적으로 확대하지 않으며 한글은 고해상도 텍스트로 별도 표시한다.
- 보존한 구버전과 개발 확인용 파생본을 포함한 공개 에셋 170개는 17.41MB다. 현재 장면은 기존 배달 그림과 인물 누끼 실험, 이전 창구 배경과 대기열을 preload하지 않는다.
- 입력과 판정은 물리적 위치로 검증한다. 타이머는 실제 경과 시간을 사용하고, 이동량만 긴 프레임을 제한한다. HUD와 안내문은 값이 바뀔 때만 갱신한다.

### 이전 배달 시안 측정 (2026-09-05)

- 새 배경·해설 카드 원본 2.71MB를 WebP 2개, 약 0.22MB로 생성했다. 새 배경은 1672×941, 투명 해설 카드는 1680×501이다.
- 전체 런타임 및 공개 이미지 159개, 16.53MB로 20MB/35MB 예산 안에 있다. 단독 도장대 시안과 편집 원본은 `assets-source/ethics-review`에만 보존한다.

- 자동 검증은 조작 거리, 빈손 판정 차단, 연습, 오답 재배달, 해설 중 시간 정지, 여섯 장 완료, 재시작, 이동 경계를 포함한다.

### 통과 기준

- 초기 화면에서 Phaser 코드는 별도 비동기 청크로 유지한다.
- 한 런타임 에셋은 2MB를 넘지 않는다.
- 실제 참조되는 런타임 에셋은 20MB 이하, `public/assets` 전체는 35MB 이하를 목표로 한다. 원본·실험본은 이 예산에 넣지 않는다.
- 새 씬은 자신의 에셋만 preload하고 다른 씬 에셋을 일괄 preload하지 않는다.
- 새 단일 소스 파일은 500줄을 목표 상한으로 하며 800줄을 넘으면 분리 계획이 필요하다.
- lint 오류 0, TypeScript 오류 0, production build 성공을 유지한다.

## 측정 명령

```bash
npm run assets:audit
npm run lint
npm run typecheck
npm run build
```

`assets:audit` 실패는 원본/중간 이미지가 `public/assets`에 섞였거나 새 파일이 예산을 넘겼다는 뜻이다. 삭제 전에 참조 여부와 원본 보존 위치를 확인한다. 원본을 수정한 뒤에는 `assets-source`에서 배포용 WebP를 다시 생성한다.
