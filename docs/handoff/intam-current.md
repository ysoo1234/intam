## 1. 새 작업의 역할

- 새 작업은 인탐 프로젝트의 총괄 0번으로서 현재 로컬 작업 폴더를 그대로 이어서 사용한다.
- 이 문서는 긴 이전 대화를 대신하는 압축된 기준이다. 오래된 채팅 내용보다 현재 저장소, `AGENTS.md`, 승인된 최신 사용자 요청을 우선한다.
- 현재 진행 중인 구현 요청은 없다. 먼저 아래 상태를 확인한 뒤 사용자의 다음 요청을 기다린다.

## 2. 절대 보존 원칙

- 현재 추적·미추적 변경, 이미지 원본, 생성 실험, 브랜치와 기존 worktree를 임의로 삭제·되돌리거나 병합하지 않는다.
- `git reset`, `git checkout --`, 임의 merge/rebase, push, 광범위한 정리 작업을 하지 않는다.
- 수정 전에 `git status --short`로 현재 상태를 확인하고, 관련 파일의 기존 변경 목적을 보존한다.
- 오래된 worktree와 이전 전문가 채팅의 결과를 자동으로 최신 기준으로 간주하지 않는다.
- 외부 공개, 운영 데이터, 비용, 핵심 학습 규칙 변경은 필요할 때 사용자 확인을 받는다.

## 3. 현재 Git 상태

- 인계를 시작할 때는 총 298개 변경 항목이 있었으나, 사용자가 새 작업을 연 뒤 직접 커밋·push했다.
- 현재 확인된 최신 커밋은 `4e4d7eb 테스팅4`이며, `git status --short`에는 이 인계 문서 폴더만 미추적으로 남아 있다.
- 앞으로는 사용자가 직접 push한 현재 저장소를 최신 기준으로 삼되, 별도 worktree와 격리 에셋은 계속 보존한다.
- 마지막 최적화 체크포인트에서 `npm run verify`가 통과했다. 인계 문서 작성만으로는 검증을 다시 실행하지 않았다.

## 4. 현재 아키텍처

- 기준 문서: `docs/architecture/README.md`
- 성능 기준: `docs/performance/budgets.md`

- 새 구현은 `src/game/features/<feature>`가 소유하고, 활성 장면과 에셋 범위는 선언형 레지스트리 및 공통 런타임 계약을 따른다.

## 6. 현재 구현 상태 요약

- 메인 월드는 새 배경·상점·비행장·윤리 심사소·게이트·분수 에셋을 사용하며 깊이 정렬, 터치 이동, 건물 진입, 충돌 영역을 여러 차례 조정했다.
- 상점은 고객별 문제 대사, 상품 카드, 제작 타이밍 게임, 공통 HUD·돌아가기 UI, 결과 흐름을 기능 폴더로 분리해 관리한다.
- 데이터 비행장은 단계별 난이도, 좋은/나쁜 데이터, 피버 패턴, 공공데이터, 질문 간격과 HUD를 조정했다.
- 윤리 심사소는 제한 시간 동안 여러 사례를 판단하는 구조, 사례 콘텐츠, 점수·생명·진행 HUD를 갖춘다.
- 시각 위치와 충돌은 사용자가 계속 직접 미세 조정하는 영역이므로, 다음 수정은 코드만 보고 끝내지 말고 로컬 화면에서 실제 이동·클릭을 확인한다.

## 8. 작업 운영 방식

- 국소 수정과 단순 확인은 총괄 또는 단일 담당자가 수행한다.
- 짧고 독립적인 조사·검증만 내부 서브에이전트에 한시적으로 맡긴다.
- worktree는 수정 경로와 완료 기준이 독립적이고 통합 이득이 큰 경우에만 사용한다.
- 선행 계약이 필요한 작업을 억지로 병렬화하지 않는다.
- 사용자에게 불필요한 중간 보고는 줄이되, 중요한 정책 선택이나 손실 위험이 생기면 쉬운 말로 멈춰서 질문한다.

## 9. 새 작업의 첫 확인 절차

1. `AGENTS.md`를 읽는다.
2. 이 문서와 `docs/architecture/README.md`, `docs/performance/budgets.md`를 읽는다.
3. `git status --short`로 기존 변경이 그대로 보이는지 확인한다.
4. 기존 변경을 정리하거나 검증을 다시 돌리지 말고, 사용자에게 인계 완료만 간단히 알린다.
5. 다음 요청부터 필요한 범위만 읽고 작업한다.
