# 인탐 비주얼 스타일 바이블

상태: `v1.0 적용 기준`  
기준 화면: `1280 × 720`  
기준 캐릭터: `assets-source/characters/midi_front.png`  
기준 보드: [`assets-source/style/intam-midi-style-board-v2.png`](../../assets-source/style/intam-midi-style-board-v2.png)

이 문서는 월드 배치를 바꾸는 기획서가 아니다. 현재 마을의 길, 화단, 분수, 건물 위치와 포털 관계는 유지하면서 캐릭터·배경·UI·효과가 한 제품처럼 보이게 만드는 제작 기준이다.

## 1. 현재 기준과 목표

인탐의 기준 스타일은 **선명한 애니메이션 라인과 부드러운 셀 음영을 쓴 장난감형 미래 마을**이다. 미디처럼 둥글고 친근한 실루엣, 크림색 몸체, 청록색 기술 요소를 사용한다. 모든 형태는 끊김 없이 닫힌 청회색 외곽선으로 명확하게 구분하며, 수채 브러시처럼 가장자리를 흐리거나 대강 칠한 질감은 사용하지 않는다. 초등학교 6학년 사용자가 첫눈에 기능을 이해할 수 있어야 하며, 장식보다 읽기와 조작이 먼저다.

현재 에셋 판단은 다음과 같다.

- 월드 건물·분수·제작소 배경·작업대는 기준 스타일과 가장 가깝다. 이 구성을 기준으로 유지한다.
- 제작소 손님은 선이 가늘고 애니메이션 일러스트 성향이 더 강하다. 전면 재생성보다 먼저 공통 그림자, 색온도, 크기, 역할표를 통일한다.
- 공항 배경은 밝고 친절하지만 데이터 아이콘은 월드보다 평면적이다. 형태를 알아보는 속도는 유지하고 외곽선·재질·광원을 보강한다.
- 윤리 심사소 배경은 차분하고 적합하지만 판정 장치가 다른 에셋보다 사실적이고 복잡하다. 장치의 세부를 줄이고 미디·마을과 같은 장난감형 재질로 맞춘다.
- 현재 코드의 공통색 `COLORS`와 둥근 글꼴 계열은 유지할 수 있다. 장면별 임의 색과 10~13px의 작은 본문은 우선 정리 대상이다.

## 2. 디자인 원칙

1. **미디가 같은 방에 있어도 어색하지 않아야 한다.** 새 인물·도구·건물은 미디의 둥근 비례, 선명하고 닫힌 윤곽, 크림·청록 재질을 기준으로 삼는다.
2. **한 화면에는 한 가지 주 행동만 가장 강하게 보인다.** 주 행동 외의 색, 빛, 움직임은 한 단계 약하게 만든다.
3. **설명은 짧게, 상태는 형태로 보여 준다.** 긴 문장 대신 아이콘, 색, 위치, 1~2줄 안내를 함께 쓴다. 색만으로 정답·위험을 구분하지 않는다.
4. **사각형과 원은 골격이지 최종 아트가 아니다.** 사건 파일, 판정 장치, 아이템 서랍처럼 장면의 역할이 드러나는 실루엣을 사용한다.
5. **배경은 따뜻하고, 상호작용은 선명하다.** 배경 대비와 채도는 낮추고 플레이 대상, HUD, 피드백만 선명하게 올린다.
6. **빛은 의미가 있을 때만 쓴다.** 청록은 도움·수집·기술, 빨강은 회피·오류, 금색은 성취에 사용한다.
7. **현재 마을 구성은 보존한다.** 비주얼 개선 때문에 길, 포털, 충돌 범위, 건물 배치를 다시 설계하지 않는다.

`Mint`, `Coral`, `Gold`, `Sky`는 넓은 본문 글자색으로 쓰지 않는다. 밝은 면에서는 `Ink` 또는 상태 본문색을 사용한다. 성공·위험은 반드시 아이콘이나 문구를 함께 제공한다.

### 3.3 채도·명도 제한

HSV 기준 권장 범위다. 이미지 생성 후 최종 보정 단계에서도 확인한다.

| 대상 | 채도 S | 명도 V | 비고 |
|---|---:|---:|---|
| 실내 벽·바닥·하늘 | 8~45% | 78~100% | 플레이 대상을 방해하지 않는다 |
| 풀·나무·큰 환경색 | 45~72% | 58~94% | 화면 가장자리와 화단에 집중한다 |
| 캐릭터·주요 소품 | 30~72% | 48~100% | 한 오브젝트 안의 고채도 면은 30% 이하 |
| HUD 표면 | 0~18% | 94~100% | 종이·크림 계열 유지 |
| 일반 강조 | 45~78% | 62~100% | 한 화면에 두 계열 이하 |
| 피버·위험 순간 효과 | 80~100% | 88~100% | 화면 면적 8% 이하, 상시 사용 금지 |

- 배경 전체에 고채도 필터를 씌우지 않는다.
- 한 패널 안에서 강조색은 기본 1개, 상태색을 포함해 최대 2개만 쓴다.
- 순수 검정 `#000000`은 사용하지 않는다. 가장 어두운 색은 `Ink` 또는 `Deep Teal`이다.
- 나쁜 데이터는 원본 그림을 붉게 물들이지 않는다. 원본 형태는 유지하고 외곽 발광만 `#FF3B30`으로 구분한다.

## 4. 형태와 재질

### 4.1 실루엣

- 캐릭터 머리·몸·손은 큰 곡선 3~5개로 먼저 알아볼 수 있어야 한다.
- 기계와 건물은 크림색 몸체, 청록색 기능 면, 코랄·금색의 작은 포인트를 기본으로 한다.
- 중요한 장치는 기능을 실루엣으로 표현한다. 승인 장치는 체크, 보완 장치는 수리 도구처럼 1초 안에 구분되어야 한다.
- 최종 UI를 단순 타원 버튼이나 색칠된 사각형만으로 끝내지 않는다. 장면 고유의 판, 서랍, 콘솔, 문서 형태를 사용한다.

### 4.2 외곽선

- 캐릭터·소품 외곽선: 짧은 변의 2~3%, 최소 2px, 최대 6px. 바깥 실루엣은 내부선보다 1~2px 굵고 모든 선은 닫혀 있어야 한다.
- 건물·큰 배경 소품 외곽선: 짧은 변의 1~2%. 멀리 있는 요소일수록 얇게 한다.
- UI 기본 외곽선: 4px. 핵심 말풍선·대표 패널만 6px까지 허용한다.
- 색은 `#315567` 82~100%를 기본으로 한다. 검정 선, 순백색 외곽선, 흐릿하거나 끊긴 브러시 테두리는 금지한다.
- 내부 선은 외곽선보다 30~50% 연하고 얇게 한다. 모든 세부에 동일한 굵은 선을 두르지 않는다.
- 부드러운 음영과 미세 질감은 닫힌 선의 안쪽에만 둔다. 나무와 벽, 잎과 하늘처럼 맞닿은 재질 사이에 번짐·빈틈·거친 붓자국이 보이면 승인하지 않는다.

### 4.3 그림자

| 대상 | 기준 |
|---|---|
| 미디·손님 실루엣 그림자 | 원본 바로 뒤, X 0~2px / Y 4~6px, 원본보다 4~8% 크게, `#315567` 16~22% |
| 지상 캐릭터 접지 그림자 | 발 아래 타원, 캐릭터 폭의 55~72%, 높이 12~18%, `#315567` 12~18% |
| 비행 미디 | 원본 바로 뒤 2~3겹, X 0~2px / Y 1~3px, 합산 18~24%; 멀리 떨어진 바닥 그림자 금지 |
| UI 패널 | X 0~3px / Y 5~8px, `#315567` 16~22%; 한 방향으로 길게 늘이지 않음 |
| 건물·소품 | 광원은 좌상단, 접지부는 짧고 부드럽게; 서로 다른 광원 방향 금지 |

캐릭터 그림자를 오른쪽으로 치우치게 복제하지 않는다. 그림자 윤곽은 원본보다 흐려야 하며, 원본을 두 장 겹친 것처럼 보이면 실패다.

### 4.4 발광과 피드백

- 좋은 데이터: 원본 실루엣을 따라 `Sky` 또는 `Mint`가 퍼진다. 원형 배경판을 넣지 않는다.
- 나쁜 데이터: 원본 색은 유지하고 실루엣형 `#FF3B30` 발광을 쓴다. 바깥 8~16%, 안쪽 22~36%, 가장자리 45~60%로 구성한다.
- 발광 최대 크기는 원본의 1.30배다. 화면 전체로 퍼지는 블룸, 흰 원, 분홍빛 위험 효과는 금지한다.
- 피버는 여러 색을 동시에 깜빡이기보다 패턴·리듬·금색 보상 효과로 즐거움을 만든다.

## 5. 라운드와 간격

기본 간격 단위는 `8px`이며 4px은 미세 정렬에만 사용한다.

| 용도 | 값 |
|---|---:|
| 화면 안전 여백 | 24px 이상 |
| 관련 요소 간격 | 8~12px |
| 서로 다른 그룹 간격 | 20~32px |
| 패널 내부 여백 | 20~28px |
| 최소 터치 영역 | 56 × 56px |
| 작은 칩 라운드 | 10~12px |
| 버튼·입력 라운드 | 16~20px |
| HUD·일반 패널 라운드 | 24~28px |
| 큰 결과·브리핑 패널 라운드 | 40~48px |

- 캡슐형은 상태 칩, 진행 표시, 짧은 라벨에만 사용한다. 모든 버튼을 타원으로 만들지 않는다.
- 한 영역 안에 중첩된 라운드 패널은 2단계까지만 허용한다.
- 같은 줄의 점수·단계·생명·시간은 고정 칸을 사용하고 글자 길이가 달라도 서로 침범하지 않게 한다.

## 6. 글꼴과 정보 계층

기본 계열은 현재 `FONT_FAMILY`의 둥근 고딕 방향을 유지한다. 출시 전에는 기기별 차이를 없애기 위해 한글 글꼴을 프로젝트에 포함하고 `NanumSquareRound` 또는 동급의 읽기 쉬운 둥근 고딕을 첫 순서로 고정한다.

| 계층 | 1280×720 기준 | 용도 |
|---|---:|---|
| Display | 40~48px, Bold | 결과, 큰 카운트다운, 한 화면 한 번 |
| Scene title | 24~28px, Bold | 장면 이름, 핵심 단계 |
| Panel heading | 21~24px, Bold | 사건·손님·질문 제목 |
| Primary body | 18~21px, Medium/Bold | 초등학생이 반드시 읽어야 하는 문장 |
| Support body | 16~17px, Medium | 조작, 짧은 설명, 메타 정보 |
| Label | 14~16px, Bold | 짧은 수치와 장식 라벨; 필수 설명에는 사용하지 않음 |

- 플레이 중 반드시 읽어야 하는 한글은 16px 미만으로 만들지 않는다. 14px은 짧은 보조 라벨에만 허용하며, 윤리 심사소의 현재 10~13px 본문은 우선 개선한다.
- 본문 행간은 글자 크기의 1.35~1.5배, 한 줄은 한글 20~28자, 최대 3줄을 권장한다.
- 본문은 밝은 종이 면 위 `Ink`로 표시하고 stroke를 쓰지 않는다. 복잡한 배경 위 짧은 문구만 4~6px stroke 또는 종이판을 사용한다.
- 작은 글자에 3px 이상의 두꺼운 stroke를 쓰지 않는다.
- 영문 대문자는 장식 라벨에만 사용하고, 학습 핵심 정보는 쉬운 한글을 우선한다.

## 7. 이미지 생성 기준

### 7.1 공통 프롬프트 템플릿

아래 템플릿의 대괄호를 작업별로 바꾼다. 미디 기준 이미지와 해당 장면 배경을 함께 참조 이미지로 제공한다.

```text
인탐 교육 게임용 [에셋 종류].
[대상과 행동], [카메라/방향], [화면 안 위치와 여백], [필요한 상태 또는 표정].
선명한 애니메이션 라인의 장난감형 미래 마을, 둥글고 친근한 큰 실루엣,
크림색 몸체와 청록색 기술 면, 코랄과 금색은 작은 포인트,
짙은 청회색의 완전히 닫힌 외곽선, 바깥선은 굵고 내부선은 얇게,
부드러운 셀 음영은 선 안쪽에만, 깨끗하게 마스킹된 가장자리,
좌상단의 따뜻한 확산광, 미디와 같은 색온도·윤곽 굵기·재질,
초등학교 6학년이 1초 안에 기능을 알아볼 수 있는 단순한 형태,
[투명 배경 또는 1280×720 전체 배경], 게임 UI가 놓일 영역은 조용하게 비움.
글자, 로고, 워터마크, 사진 질감, 검정 외곽선, 과도한 네온,
복잡한 작은 부품, 날카로운 모서리, 강한 원근 왜곡, 수채 번짐,
거친 붓 가장자리, 끊긴 선, 스케치 선은 제외.
```

### 7.2 에셋별 추가 문장

- **투명 캐릭터/소품:** `전체 실루엣이 프레임 안에 들어오며 가장자리 8% 안전 여백, 바닥 그림자 없음, 투명 배경.`
- **표정 쌍:** `몸·의상·카메라·크기는 완전히 동일하고 얼굴과 손동작만 [걱정/기쁨]으로 변경.`
- **배경:** `전경·중경·후경 깊이는 분명하되 플레이 영역의 대비와 디테일을 20% 낮춤.`
- **UI 장치:** `문구가 들어갈 평평한 면을 비워 두고 글자는 생성하지 않음, 기능 아이콘만 형태로 표현.`
- **타일 배경:** `좌우 경계의 색과 형태가 이어지고 반복 지점에 큰 랜드마크를 두지 않음.`

### 7.3 생성 후 처리

1. 편집 원본과 생성 결과는 `assets-source`에 보관한다.
2. 잘못 생성된 글자·워터마크·색 번짐·반투명 가장자리를 제거한다.
3. 같은 장면의 기준 에셋과 나란히 놓고 색온도, 윤곽, 광원, 해상도를 맞춘다.
4. 런타임 파일은 의미 있는 영문 kebab-case 이름으로 만들고 WebP로 최적화한다.
5. `public/assets`에는 실제 참조되는 파생 파일만 둔다.
6. `npm run assets:optimize`, `npm run assets:audit`, 관련 화면 검증을 통과한 뒤 승격한다.

### 7.4 현재 기준판 생성 기록

- `intam-midi-style-board-v1.png`: 미디를 캐릭터·색·재질 기준으로 사용해 환경 조각과 공통 UI의 첫 기준판을 생성했다.
- `intam-midi-style-board-v2.png`: v1의 구성은 유지하고 사용자가 지적한 거친 나무·길 가장자리를 미디와 같은 선명한 외곽선으로 다시 제작했다. 앞으로는 v2만 제작 기준으로 사용하며 v1은 변경 이력으로 보존한다.
- 생성 방식: Codex 내장 이미지 생성의 참조 이미지 편집 모드. 런타임 에셋이 아니라 `assets-source/style`에 보존한 제작 참고 자료다.
- 최종 교정 프롬프트의 핵심: `Preserve the board composition. Give every character, building, tree, path stone, plant, fountain and UI element a precise, fully closed 2–4 px dark desaturated blue-gray outline like Midi; keep soft cel shading strictly inside the contours; remove watercolor fringe, paint bleeding, rough brush edges, broken lines and sketch seams.`

## 8. 금지 예

- 최종 선택지를 단색 사각형·원·타원만으로 표현하는 것.
- 미디 옆에 사진풍, 금속 실사풍, 극단적 3D 렌더를 그대로 놓는 것.
- 캐릭터 그림자를 오른쪽이나 아래 멀리 복제해 잔상처럼 보이게 하는 것.
- 위험 오브젝트 전체를 붉게 물들이거나 분홍·자주색 빛으로 위험을 표현하는 것.
- 좋은 데이터와 나쁜 데이터 뒤에 흰 원 또는 불투명 원판을 넣는 것.
- 작은 한글에 두꺼운 외곽선, 16px 미만 핵심 본문, 긴 튜토리얼 문단을 쓰는 것.
- 이모지, 임시 도형, 프로그래밍으로 만든 기본 아이콘을 출시용 핵심 아트로 남기는 것.
- 장면마다 다른 라운드 값, 그림자 방향, 글꼴, 검정 농도를 임의로 쓰는 것.
- 한 화면에서 청록·빨강·보라·노랑·무지개 발광을 동시에 상시 재생하는 것.
- 이미지 안에 생성형 글자를 넣는 것. 모든 실제 문구는 코드 텍스트로 올린다.
- 비주얼을 맞춘다는 이유로 현재 마을 배치, 포털 접근, 충돌 영역을 바꾸는 것.

## 9. 장면별 적용 우선순위

### P0 — 공통 토큰과 가독성

- `COLORS`, 글꼴 계층, 8px 간격, 패널·버튼·그림자 규칙을 공통 primitive로 고정한다.
- 핵심 본문 최소 16px, 조작 안내 최소 16px를 모든 장면에 적용한다.
- 색만으로 상태를 전달하는 UI와 단순 타원 선택지를 먼저 제거한다.

### P0 — 윤리 심사소

- 사건 파일의 10~13px 설명을 15~18px로 재배치하고 정보량을 2개 사실+한 질문으로 제한한다.
- 승인·보완 장치는 현재 기능 실루엣을 유지하되 세부와 사실적 금속 질감을 줄여 장난감형 재질로 통일한다.
- 브리핑, HUD, 사건 파일, 피드백의 제목 위치와 텍스트 칸을 고정한다.
- 사무실 배경 구성은 유지하고 읽는 영역 뒤의 대비만 낮춘다.

### P0 — 데이터 비행 공항

- 좋은/나쁜 데이터의 발광을 같은 실루엣 규칙으로 통일하고 색만 청록/빨강으로 구분한다.
- 평면 아이콘에 2~3px 청록 외곽선, 크림 하이라이트, 한 방향 음영을 더해 월드 소품과 맞춘다.
- 점수·단계·생명·시간은 고정 4칸 HUD로 유지하고 모든 숫자의 중심선과 여백을 통일한다.
- 배경 반복 경계와 해상도 차이를 확인하되 현재 비행 동선과 속도는 비주얼 작업에서 바꾸지 않는다.

### P1 — 생활 속 AI 제작소

- 현재 배경·작업대·아이템 패널을 장면 기준 에셋으로 유지한다.
- 손님은 원본 바로 뒤 실루엣 그림자, 동일한 바닥선, 동일한 역할표 크기로 통일한다.
- 손님 표정 쌍의 몸·의상·크기를 잠그고 표정과 작은 손동작만 변경한다.
- 상품 이모지는 임시 표현으로 표시하고, 우선순위가 높은 상품부터 같은 스타일의 투명 소품으로 교체한다.

### P1 — 월드

- 현재 길·화단·건물·분수·포털 배치는 유지한다.
- 미디와 건물의 앞뒤 가림, 접지 그림자, 입장 안내판의 규칙만 통일한다.
- 새 건물은 현재 다섯 월드 에셋의 카메라 각도, 바닥선, 외곽선 굵기, 색온도를 그대로 따른다.
- 월드 전체 재생성은 하지 않는다. 부분 교체 시 기존 충돌·포털과 독립적으로 검증한다.

### P2 — 향후 맵과 AI 월드

- 새 맵은 이 문서의 토큰과 프롬프트를 먼저 사용해 기준판 1장, 건물 1개, UI 1개를 검증한 뒤 일괄 생성한다.
- 검증되지 않은 새 화풍을 한 장면 전체에 먼저 확장하지 않는다.

## 10. 비주얼 QA 체크리스트

### 스타일

- [ ] 미디 옆에 두었을 때 윤곽 굵기, 색온도, 광원 방향이 자연스럽다.
- [ ] 배경보다 플레이 대상과 주 행동이 먼저 보인다.
- [ ] 한 화면의 주요 강조색이 두 계열 이하이다.
- [ ] 순수 검정, 사진풍 재질, 과한 금속 세부, 생성형 글자가 없다.
- [ ] 현재 월드 배치와 포털 위치가 바뀌지 않았다.

### 읽기와 조작

- [ ] 반드시 읽어야 하는 한글이 16px 이상이다.
- [ ] 본문은 최대 3줄이며 배경과 충분히 분리된다.
- [ ] 터치 영역이 56×56px 이상이고 인접 행동 사이 간격이 12px 이상이다.
- [ ] 성공·위험·선택 상태를 색 외의 아이콘·문구·형태로도 구분한다.
- [ ] 점수, 단계, 생명, 시간이 어떤 값에서도 겹치지 않는다.

### 그림자와 효과

- [ ] 캐릭터 실루엣 그림자가 원본 바로 뒤에 있고 옆으로 밀리지 않는다.
- [ ] 지상 캐릭터가 바닥에 붙어 보이고 비행 캐릭터에는 먼 바닥 그림자가 없다.
- [ ] 좋은/나쁜 데이터의 발광은 원형 판이 아니라 원본 실루엣을 따른다.
- [ ] 위험빛은 선명한 빨강이며 분홍·자주색으로 보이지 않는다.
- [ ] 상시 깜빡임, 큰 블룸, 여러 색 무지개 효과가 읽기를 방해하지 않는다.

### 에셋과 성능

- [ ] 원본은 `assets-source`, 런타임 파생본은 `public/assets`에 분리되어 있다.
- [ ] 런타임 이미지는 의미 있는 이름, 적절한 크기, WebP 형식과 올바른 알파를 가진다.
- [ ] 좌우 반복 배경은 경계에서 끊기지 않는다.
- [ ] 1280×720 원본과 축소 화면에서 글자·아이콘·외곽선이 깨지지 않는다.
- [ ] `assets:optimize`, `assets:audit`, lint, typecheck, build 및 장면별 스크린샷 검증을 통과한다.

## 11. 승인 기준

새 비주얼은 다음 네 질문에 모두 `예`일 때만 런타임 에셋으로 승격한다.

1. 미디와 같은 제품의 그림처럼 보이는가?
2. 1초 안에 무엇이고 어떻게 상호작용하는지 알 수 있는가?
3. 글자와 상태가 장식보다 먼저 읽히는가?
4. 기존 장면 구성·게임 규칙·성능 예산을 해치지 않는가?
